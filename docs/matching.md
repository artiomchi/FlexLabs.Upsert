# Matching rows

`On()` tells the database which columns identify an existing row. If a row with the same values exists, it is
updated, otherwise a new one is inserted.

```csharp
.On(c => c.ISO)                         // a single column
.On(v => new { v.UserID, v.Date })      // a composite key
```

If you leave `On()` out, the primary key is used, provided it isn't database-generated.

## Requirements

**The columns need to be unique.** A primary key, or a unique index. Databases can only detect a conflict through
a unique constraint, and the upsert statement relies on it.

**They can't be database-generated.** That includes identity/auto-increment columns and `Guid`s generated by the
database. The values in your entity wouldn't match anything in the table, and on insert the database would
ignore them anyway. If you already know the generated key of a row, you want a normal update, not an upsert.

If you do use generated columns in `On()`, you'll get an `InvalidMatchColumnsException`.

## Generated columns

EF Core marks `Guid` and `string` primary keys as generated by default, even if you always assign them yourself.
Tell EF that the value comes from your code:

```csharp
[Key, DatabaseGenerated(DatabaseGeneratedOption.None)]
public string ID { get; set; }
```

or in the model:

```csharp
modelBuilder.Entity<Country>().Property(c => c.ID).ValueGeneratedNever();
```

If you really do need to match on a generated column, `AllowIdentityMatch()` turns the check off.

## Nullable columns

Matching on a key that includes a nullable column is only supported on SQL Server and the in-memory provider,
where two `NULL`s are treated as equal. Avoid nullable match columns on the other databases.

## MySQL

MySQL doesn't take a match expression. It matches on whichever unique key conflicts, so `On()` has no effect.
Make sure the table has the unique index you expect.
